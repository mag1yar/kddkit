# Self-accept needs the user to say so

## Decision
`review → done` для актора, который сам сдал задачу в review, по умолчанию запрещён (`checkMove`, сравнение по `authorOf`; автор берётся из журнала — последнее `moved` с `to: review`). Запрет снимается `--reason`: сказанное вслух «закрой» — легальный путь. Такой переход помечается в событии `moved` полем `self_accepted: true`, а сам reason, как и раньше, ложится комментарием к задаче. Человек не ограничен ничем; любой другой актор принимает без reason.

## Rationale
Правило существует против молчаливого самозакрытия — агент, доделавший работу ночью, не должен сам же признать её принятой. Оно не должно стоять против прямой просьбы: если пользователю проще сказать «закрой», чем открыть доску, запрет добавляет ему шаг и ничего не проверяет — работу всё равно никто не посмотрел, просто теперь и закрыть некому.

Предыдущая формулировка закрывала и `--reason`. Практический эффект: у агента, которому велели закрыть свою задачу, не оставалось честной команды, зато оставалась нечестная — `KDD_ACTOR=user`, которая одним движением выключает ещё и гейт критериев, fence по lease и матрицу переходов. Гейт, толкающий к худшему обходу, чем тот, что он запрещает, работает против себя.

Отметка `self_accepted` — то, ради чего запрет вообще стоил кода: «принял сам себя по просьбе» остаётся отличимым от «принял кто-то другой» в журнале, а не растворяется в общем `moved`.

## Alternatives
- **Оставить `--reason` закрытым** (предыдущее решение). Честнее на бумаге, дороже в жизни: пользователь кликает вместо того, чтобы сказать, а спуфинг личности остаётся открытым и обходится дороже для аудита.
- **Отдельная команда приёмки только для человека** (`kdd accept`). Не решает исходную жалобу: пользователь всё равно печатает команду сам, вместо того чтобы попросить.
- **Спрашивать подтверждение у пользователя перед закрытием.** Подтверждение и есть та самая просьба — второй вопрос на ту же тему.
